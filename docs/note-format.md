# 笔记格式

构建器读取配置中 vaultDir 内的 Markdown。每篇笔记开头使用以下格式；这只是一个虚构示例：

```markdown
---
type: 项目
domain: 项目与实践
updated: 2030-04-17
tags: ["示例","实践"]
fictional: true
---

# 阳台花园

这里记录参与、选择、进展与变化。

关联：[[领域/项目与实践]]。
```

## 字段

- type：人物、偏好、课程、项目、作品、记录、状态、索引、规则之一。
- domain：六个主领域或档案入口之一。
- updated：有效的 YYYY-MM-DD 维护日期，不能代替正文的事件时间。
- tags：JSON 字符串数组，可省略为空数组；不支持完整 YAML 语法。
- fictional：演示资料必须为 true；个人档案不要标记为虚构。
- graph：设为 false 时可从球面隐藏，但正文仍嵌入生成页面；类型为规则时默认隐藏。

AGENTS.md、点号开头的目录、依赖、原件、导出、缓存与模板目录不作为笔记读取。目录内的符号链接会被拒绝，避免无意读取目录外资料。

## 双链

支持从笔记目录根开始的路径、唯一短名、显示别名和笔记标题片段，例如：

```text
[[领域/项目与实践]]
[[阳台花园]]
[[项目/阳台花园|我的小花园]]
[[项目/阳台花园#重要变化]]
```

建议使用完整路径。短名重复或目标不存在时构建失败；代码块和行内代码中的示例双链不参与校验。标题片段当前按目标笔记解析，阅读器从笔记顶部打开。

## 显示与输入边界

一份笔记可没有关联；构建器会提示孤立节点，不会凭空生成关系。初始节点由配置的 profileId 指定，省略时优先选择人物，其次选择第一个节点。

程序只处理指定目录内已有 Markdown。图片、附件、账号、聊天导出与计算机使用历史由使用者自行选择和整理，不会被核心程序自动采集。

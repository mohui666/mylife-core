# 定时整理接入说明

整理方法、数据输入和调度分别配置。mylife-core 负责校验与生成；AI 读取哪些记录、如何定时启动，由使用者已经授权的工具决定。

## 接入方式

先把通用提示词中的 VAULT_DIR 和 CONFIG_FILE 替换为自己的私有笔记目录与本地配置。把它交给已有的 AI 工具或调度器，选择合适的运行频率。

只读取本人明确授权且工具有权访问的数据。不要把账号配置、凭据、历史对话或操作记录打包进公开仓库。未配置数据接口时，直接手工编辑 Markdown 也能使用核心图谱。

## 通用提示词

```text
维护 VAULT_DIR 内的个人档案。先阅读 docs/organization-rules.md 和已有概况、当前状态、领域入口，遵守使用者最新的更正、排除和删除要求。

仅处理已经明确授权提供的新增记录。首次运行由使用者指定时间范围；后续优先处理上次成功整理之后的内容，仅在确认上下文、先后与范围时回看旧记录。按实际事件时间理解，不把文件更新时间当成事件时间。

筛选关于本人的有意义信息，每篇选择一个主领域。先找已有对象与概览，将新进展合并到原页，必要时才新建独立对象。完整正文只维护一份，当前状态写仍有效的情况，时间线记重要变化，入口负责导航。

不保存知识讲解、教程、题目答案和零碎操作，不把一次询问或 AI 的建议当成本人长期偏好或决定。不从旧记录重新引入已删除的条目，不恢复历史暂停的任务，不对外发送消息。

写入有效的 domain、type、updated 和少量 tags，维护有具体含义的双链。完成后使用现有 Node.js 执行：node scripts/build.mjs --config CONFIG_FILE。构建失败时说明实际问题，不把未读时间段记为已处理。

仅在成功处理后更新私有目录中的整理进度文件；不要把真实资料写入 examples/demo 或 demo.html。没有实质变化时不重复改写和通知；只有有意义的更新、失败或需要使用者处理时才简短报告。
```

本文件提供流程模板，不会创建后台任务、连接账号或改变任何已有调度。
